# Проверка PWA 0.2.0 — 2026-10-11

## Результат

### Подготовка Vercel

- На исходной локальной структуре TS18003 не воспроизводится: `src/` присутствует и не исключается `.gitignore`.
- После добавления `vercel.json` и явных шаблонов `tsconfig.json` повторный `npm run build` прошёл: проверка TypeScript, Vite и генерация Service Worker. Функциональные исходники не менялись.
- Попытка `npm ci` в текущем Windows-окружении остановилась на `EPERM`: работающий процесс удерживает бинарник esbuild. `npm install` восстановил зависимости, после него сборка завершилась успешно. Чистая установка через `npm ci` в этом запуске не подтверждена.
- GitHub/Vercel не подключены к рабочей папке: `.git` отсутствует. Состав удалённого коммита, выбранный Root Directory и успешность deployment не проверены. Для устранения удалённого TS18003 нужно загрузить полную структуру из `GITHUB_UPLOAD.md` и выбрать её корень в Vercel.

### Проверки PWA до подготовки публикации

- `npm run build` — успешно: TypeScript, Vite, генерация Service Worker с версией и полным перечнем ресурсов. Готовая PWA: `dist/`.
- `npm test` — **10/10**: деньги, даты, прогресс, валидация импорта, совместимость старого JSON, отклонение неверных ID, дат и значений.
- `npm run test:ui` — **8/8** сценариев в Microsoft Edge на production-сборке, с настоящими IndexedDB и Service Worker.
- Дополнительно повторно пройден тест полного перезапуска с проверкой `Page.getInstallabilityErrors`: **пустой список ошибок**, PWA соответствует проверке устанавливаемости Edge в обычном постоянном профиле.
- Проверен мобильный экран **375×812**: все разделы и форма создания задачи без горизонтального переполнения; скриншот просмотрен.
- npm после удаления зависимостей Tauri сообщил **0 уязвимостей**.

## Браузерные сценарии

1. Данные и кэш сохраняются после полного закрытия браузера и запуска нового процесса с тем же профилем, при отключённой сети. Проверена устанавливаемость.
2. Планировщик передаёт напоминание системному API и сохраняет квитанцию в настоящем IndexedDB. После перезагрузки прежнее напоминание не повторяется, новое доставляется.
3. Реальное скачивание JSON, импорт обратно, совместимость старой настройки трея, отказ от повреждённого файла без изменения данных.
4. Перезагрузка и открытие нового окна офлайн; изменение задачи и доступность всех семи разделов без сети.
5. Мобильная навигация и редактирование.
6. Устаревшая вкладка не перезаписывает изменения из другой вкладки.
7. Создание, выполнение, перенос, изменение, перезагрузка и удаление действия.
8. CRUD упражнений, денежных операций, проектов и их задач, целей и напоминаний.

## Границы проверки

- Тест напоминаний подменяет только `showNotification`, не проверяет видимый баннер ОС. Разрешение уведомлений задаётся браузерному тестовому профилю. Планировщик и IndexedDB не подменяются.
- Физические Android/iPhone и ручная установка на их главный экран не проверялись. Манифест, иконки, standalone-режим и проверка устанавливаемости проверены в Edge; инструкция Safari присутствует в интерфейсе.
- Публикация не выполнялась. Для установки на телефон нужен статический HTTPS-адрес сборки. HTTP по локальному IP и `file://` не подходят.
- Закрытая PWA не имеет надёжного локального планировщика системных уведомлений без push-сервера. При открытом приложении работает проверка; в фоне браузер может её задерживать. Это явно указано пользователю.
- Старые native/SQLite-исходники сохранены, но не входят в новую сборку и не нужны для запуска.

Исправленный в ходе проверки дефект: заголовок `Vary: Origin` статического сервера мешал читать CSS/JS из precache для модульных запросов. Service Worker теперь игнорирует Vary только при поиске в собственном кэше неизменяемых локальных ресурсов.
